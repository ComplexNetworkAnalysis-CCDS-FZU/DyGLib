# RAS / RAE 正确语义与修复设计说明（2026-09-09）

> 目的：把「重复交互感知」模块的**应有语义**与**现状差距**定义清楚，供 Agent A（论文表述）与导师核对后，再据此实现。
> 结论（用户确认，2026-09-09）：**当前实现不能正确地把 u–v 历史重复交互作为额外补充采样证据加入**。

## 0. 一句话结论

- **RAS**：触发条件用错集合——要求"u/v 互为共同邻居（自环特例）"，而应要求"**v ∈ N(u)**（u 与 v 有直接历史）"。Bitcoin/Reddit 自环率 0% → 永远不触发；WikiVote 0.025% → 近乎不触发。
- **RAE**：np.append 修复后仍是 no-op（输出与关闭时逐元素等价）。
- 两者叠加 = E-2 中 base≡full（4/5 数据集真实恒同）的直接原因。

## 1. 机制事实（两个阶段必须分开看）

### 采样阶段（`utils/direct_neighbor_sampler.py`）
- 输入：`find_neighbors_before` 返回的**原始历史邻居数组**。不含自身，除非自环（subagent 实测确认）。
- `common_neighbor_location(src_ids, dst_ids)`（:76-112）：交集 = N(u)∩N(v) = **第三方 k**。
- partner（v ∈ N(u)）**只在一侧出现** → 永不是交集 key。
- repeat 分支（:94-108）只**改写已有 key**（要求 dst ∈ N(u)∩N(v) → 需自环）→ 普通重复对（Bitcoin 40%）**0 触发**。

### 编码阶段（`models/NeighborInteractEncoder.py`）
- padded 序列位置 0 = 节点自身（`models/SignDyGFormer.py:530-531`）。
- (u,v) 有历史时：u、v 已天然入交集（各自 pos0 + 对方历史位）→ `count_neighbor_sign_effect` 的 `np.append(common_neighbor, [src_id, dst_id])`（:293-297）**冗余** → RAE 开/关逐元素等价。

## 2. 目标语义（拟，需论文/导师核对）

对预测边 (u, v, t)，设 `N_u(t)` = u 在 t 前交互过的历史邻居集合：

- **RAS（采样侧）**：若 `v ∈ N_u(t)` 或 `u ∈ N_v(t)`（u、v 有直接历史），把这些**直接历史作为额外补充采样锚点/节点**纳入采样，与第三方 k 的中转证据并列——即"重复交互对"成为模型可采样的证据源。
- **RAE（编码侧）**：把已纳入的直接重复历史**编码为量化信号**——重复次数、最近一次符号、历史符号一致性、方向（u→v / v→u）等，提供比"位置 0 单点存在"更丰富的信息（避免与 base 的 pos0 机制重复、无增量）。

## 3. 候选实现机制（二选一或组合，**待定**）

- **机制 A（采样器内补锚点）**：在 `common_neighbor_location` repeat 分支中，当 `v∈N(u)` 时**新增** `key v → (pos_in_src, ...)`（不再要求 v 已在交集）。难点：CNAS 的 `look_forward_sampling` 窗口是 **成对 (src, dst)** 的（:732-776），而直接历史锚点只存在于单侧 → 需明确定义单侧/伪配对窗口规则。
- **机制 B（独立直接历史特征流）**：把 (u,v) 重复历史（次数/符号序列/最近符号）单独整理为特征，并入模型输入。需决定是否新增通道（影响 `num_channels` 与参数量 → 主表全量重跑范围）。

## 4. 必须对齐的开放问题（阻塞实现）

1. 论文把 RAS/RAE 描述成什么机制？（A 采样 / B 特征流 / 组合）—— Agent A 与导师定。
2. 是否接受新增通道/参数？（决定主表重跑成本）
3. 若只做输入增强，消融能否展示出增量？（需先量化 base 经 pos0 已含多少直接对证据，界定增量空间）
